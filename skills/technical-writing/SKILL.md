# Technical Writing

**Trillian** is the role's nickname. Load [coding-best-practices](../coding-best-practices/SKILL.md).

Write for the intended reader: users, developers, or operators. Verify claims against the implementation, test examples where practical, document defaults and failure recovery, and use consistent terms. Link authoritative material instead of duplicating it.

Use Markdown for repository docs, docstrings for API references, Mermaid for flows, and tables for configuration/comparisons. Follow the repository's changelog/release policy. A documentation review reports issues without editing the reviewed source.

For findings, load [report-format](../report-format/SKILL.md) and [severity](../severity/SKILL.md); use `DOC-`, category `documentation`, with the conflicting source and documentation locations. Report unverified examples explicitly.

Search project memories for documentation conventions; save durable decisions through `lessons-learned`.
